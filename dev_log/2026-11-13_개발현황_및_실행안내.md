## 1. 현재 개발 단계 요약

현재 폴더에는 **계정 인증 서버와 학사 업무용 JavaScript 모듈들이 각각 구현되어 있다.** 인증 모듈은 가입·로그인·세션 확인·로그아웃을 처리하는 로컬 웹 화면과 서버를 갖췄다. 성적 입력·조회 및 평점 계산, 학점 집계, 성적 그래프와 상대평가 인원 계산은 함수와 모듈 단위로 작성되어 있다. 인증·성적·평점·학점 계산 테스트 파일이 있지만 그래프 모듈 전용 테스트 파일은 확인되지 않았다.

다만 학사 모듈을 로그인 서버나 실제 웹 페이지에 연결한 흔적은 확인되지 않는다. 최상위 `index.html`은 간단한 자리표시자 페이지이고 `server/app.js`가 공개하는 화면은 로그인 관련 파일뿐이다. 따라서 현 상태는 **로그인 기능은 독립 실행 가능하고, 학사 계산 기능은 모듈 단위 구현 및 테스트 코드가 준비되어 있지만, 사용자가 화면에서 통합적으로 쓰는 학사 서비스까지 완성되지는 않은 단계**다.

## 4. 실행 방법

### 4.1 로그인 웹 서버 실행

PowerShell에서 프로젝트 폴더로 이동해 다음을 실행한다.

```powershell
Set-Location -LiteralPath 'D:\programming_folder\2026 ENDPoinT'
node --version
npm start
```

Node.js 24.12.0 이상이 필요하다. 기본 설정에서 서버는 `http://localhost:3000`으로 열리며, 브라우저에서 다음 주소를 사용한다.

**http://localhost:3000/login.html**

서버가 로그인 HTML과 인증 API를 함께 제공해야 한다. HTML 파일을 직접 열거나 Live Server로 여는 방법은 인증 서버를 실행하지 않는다. 종료하려면 서버가 실행 중인 PowerShell에서 `Ctrl+C`를 누른다.

`npm run dev`는 Node watch 모드로 서버를 실행한다. 화면 코드를 수정한 경우 브라우저도 새로고침한다.

### 4.2 설정

기본값으로 실행할 때 `.env`는 필수가 아니다. 사용자 지정 포트·호스트·접속 출처·DB 경로가 필요하면 `.env.example`을 참고해 `.env`를 설정한다. `PORT`를 바꾸면 `APP_ORIGIN`의 프로토콜·호스트·포트도 실제 접속 주소와 일치시켜야 한다. 기본 서버는 로컬 접속용 주소에 바인딩된다.

### 4.3 학사 JavaScript 모듈

성적·학점·그래프 모듈에는 `package.json` 기준 별도 실행 서버나 사용자 화면이 지정되어 있지 않다. 이 모듈은 브라우저 페이지나 다른 JavaScript 코드에서 import해 호출하도록 작성되어 있다. `grades.js`의 저장 기능은 브라우저 `localStorage`를 사용하므로 서버 프로세스만 실행한다고 학사 화면이 열리지는 않는다. 그래프 대시보드도 DOM 컨테이너에 `mountGradeDashboard(...)`를 호출해 연결해야 한다.

테스트 명령은 다음과 같이 정의되어 있다. 요청에 따라 이번 문서 작성에서는 실행하지 않았다.

```powershell
npm test
```

## 5. 데이터와 계산 정책에서 확인할 사항

- 예시 학사 데이터(`data/*.json`)는 존재하지만, 현재 로그인·학사 코드 사이에서 자동으로 연결되는 로더나 사용자별 저장 API는 확인되지 않는다.
- `grades.js`의 과목은 브라우저 로컬 저장소에 보관되며 서버의 로그인 계정 데이터와 동기화되지 않는다.
- `data/grading_policy.json`의 등급별 비율은 `0.15` 같은 소수 비율로 저장되어 있다. 반면 `calculateGradeRanges`와 그래프 대시보드는 `15`처럼 퍼센트 숫자(0~100)를 기대한다. 그대로 연결하면 15%가 0.15%로 해석되므로 입력 규격을 통일하거나 변환해야 한다.
- 성적 입력 모듈은 `major`·`minor`·`general` 분류를 지원하지만 그래프 구분은 `all`·`major`·`general`만 제공한다. 부전공 그래프까지 필요하면 그래프 모듈 확장이 필요하다.
- 학년별 수료 기준을 계산하는 함수는 있으나, 전체 졸업 요건 충족 판정과 같은 의미는 아니다.
- 재수강 및 중복 과목 학점 처리 정책은 확정되어 있지 않다. 평균평점, 취득학점, 졸업 인정학점의 규칙이 서로 다를 수 있으므로 실제 학교 기준을 정한 뒤 통합해야 한다.
- 예시 데이터만으로 학교의 공식 졸업요건이나 사용자의 실제 학적을 판단해서는 안 된다.

## 6. 다음 개발 단계

1. 학사 업무 화면을 만들고 성적·학점 모듈을 해당 화면에 연결한다.
2. `data/*.json`을 실제 데이터 공급원으로 쓸지 정하고, 로그인 사용자 정보와 과목 기록의 저장·불러오기 방식을 결정한다. 평가 비율은 소수와 퍼센트 중 하나로 규격을 맞춘다.
3. 학과·입학 연도·교육과정에 맞는 공식 졸업 기준과 재수강·F·P/F·영역 중복 인정 규칙을 확정한다.
4. 계산 결과의 근거와 미충족 요건을 보여 주는 졸업요건 판정 흐름을 구현한다.
5. 통합 화면에서 가입부터 학사 데이터 확인까지 연결하고, 요구사항에 맞는 검증을 수행한다.

**현재 실행 가능한 서비스 범위는 로그인 웹 모듈이다.** 학사 기능은 계산·조회용 코드가 일부 준비되어 있으나 실제 서비스 화면 및 계정별 데이터 흐름으로 통합하는 작업이 남아 있다.
